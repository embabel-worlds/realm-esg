Populate the ESG corpus

Spider each organization's published material, chunk it into the corpus, and let the extractor read typed, cited observations from it.

A bare domain is crawled from its homepage (apex then www.), following links that look like sustainability material in any of the languages these sites are written in. A full URL is ingested directly — including a PDF, which is usually where the real reporting is. Corporate homepages geo-redirect, require JS and block non-browser clients; when one resists, paste its sustainability report URL instead.

URL exclusions

Regular expressions matched against each crawled URL, case-insensitively. A page dropped here is never fetched, so it costs no chunks, no embeddings and no extraction call. Defaults ship in esg-population.json; edits here apply to this run only.

This fetches pages from third-party websites and costs one extraction call per document the first time it is read. Nothing here runs on a schedule — the corpus only ever grows when someone presses this.

How it works

    
The data

    
This page writes the corpus the ESG realm reads. Each target is either crawled (a bare domain:
    apex, then www.) or ingested directly (a full URL, including a PDF). Every page kept is
    ingested server-side — fetched, converted, chunked and embedded — as a Document tagged
    esg and attributed to the organization's domain. Observations are then read from each
    document by the realm's esgExtraction producer and kept in the graph
    (cache: { kind: graph }). Nothing runs on a schedule: the corpus changes only when
    someone presses Populate. Crawl hint, URL exclusions, page budget, delay and the refetch window
    default from esg-population.json, shipped beside this app; edits on the page apply to
    this run only.

    
The questions

    
Writes go through two fixed endpoints; reads through named views
    (POST /api/v1/views/{name}/invoke). The browser never sends Cypher.

    
    
      
  • crawl tool (POST /api/v1/tools/crawl, args url,
      hint, max_pages) — lists the pages under a domain, ranked by the crawl
      hint. Pages matching an exclusion pattern are dropped before any fetch; include hints only
      reorder.
    • 
      
  • Ingest a URL (POST /api/v1/documents/url, body url,
      fromOrgDomain, tags: ['esg']) — one call per page or report.
    • 
    

    
EsgCoverage — What the corpus holds per domain. Fills the Coverage table, and its lastIngestedEpochMs decides which domains are inside the refetch window and skipped. No parameters.
MATCH (d:Document) WHERE 'esg' IN d.tags
WITH d, [t IN d.tags WHERE t STARTS WITH 'domain:'][0] AS dt
WITH d, coalesce(
       CASE WHEN dt IS NULL THEN null ELSE substring(dt, 7) END,
       replace(split(replace(replace(d.uri, 'https://', ''), 'http://', ''), '/')[0], 'www.', '')
     ) AS domain
OPTIONAL MATCH (c:ContentElement)-[:HAS_PARENT*]->(d:Document)
WITH domain, d, count(DISTINCT c) AS chunkCount
RETURN domain,
       count(DISTINCT d) AS documents,
       sum(chunkCount) AS chunks,
       max(d.ingestionEpochMs) AS lastIngestedEpochMs
ORDER BY domain

    
EsgDatapointCatalogue — Checked at the start of a run; no rows means the reference catalogue is not seeded in the graph, which the log reports. No parameters.
MATCH (dp:EsgDatapoint)
OPTIONAL MATCH (dp:EsgDatapoint)-[:SATISFIES]->(r:EsgRequirement)-[:IN_FRAMEWORK]->(f:EsgFramework)
RETURN dp.id AS datapoint, dp.name AS name, dp.answerType AS answerType, dp.unit AS unit,
       dp.sourceClass AS sourceClass,
       collect(DISTINCT f.name) AS frameworks,
       collect(DISTINCT r.code) AS requirementCodes
ORDER BY dp.answerType, dp.id

    
EsgDocuments — The ingested documents for a domain with chunk counts: the work list for reading. Parameters: domain.
MATCH (d:Document) WHERE 'esg' IN d.tags AND d.uri CONTAINS $domain
OPTIONAL MATCH (c:Chunk)-[:HAS_PARENT*]->(d:Document)
RETURN d.uri AS uri, d.title AS title, count(c) AS chunks
ORDER BY chunks DESC

    
EsgExtractDocument — Reads ONE document and returns its observations, materializing extraction (one model call per window) on first read. Called once per document after ingestion. Parameters: uri.
MATCH (d:Document {uri: $uri})-[:HAS_OBSERVATIONS {ai: {materialize: true}}]->(o:EsgObservation)
WITH o.datapointId AS dpId, collect(o) AS obs
WITH dpId, obs, [x IN obs WHERE x.value <> 'not_disclosed'] AS said
WITH dpId,
     CASE WHEN size(said) > 0 THEN said[0] ELSE obs[0] END AS o,
     size(said) AS windowsDisclosing,
     size(obs) AS windowsRead
RETURN o.docUri AS document, dpId AS datapoint, o.value AS value,
       o.unit AS unit, o.period AS period, o.quote AS quote, o.sourceChunkId AS chunkId,
       windowsDisclosing, windowsRead
ORDER BY datapoint


    
When it looks wrong

    
    
      
  • current — last read Nd ago … Skipped: the domain was ingested inside the refetch
      window. Set Refetch after to 0 to force a re-read. Freshness is per domain, not per URL.
    • 
      
  • crawled but no page carried a url / no crawlable entry point: the site
      geo-redirects, needs JavaScript or blocks non-browser clients. Paste the sustainability report URL
      instead.
    • 
      
  • every page was excluded: the exclusion patterns matched everything the crawl found.
    • 
      
  • Documents are in but nothing was read from them: ingestion succeeded and extraction
      returned no observations.
    • 
      
  • A heavy document takes tens of seconds to ingest and longer to read; the log names each URL
      before its call so a slow one is not mistaken for a hang. Stop takes effect at the next document
      boundary.
    • 
      
  • Coverage empty (nothing assessed yet) means no esg document is in the
      corpus; coverage unavailable means the view could not be read.
    • 
    

    
What made this possible

    
Ingestion, crawling and extraction are the appliance's own: the page calls a tool and an
    ingestion endpoint, then reads documents through a view whose traversal of a virtual join
    (HAS_OBSERVATIONS, with an explicit materialize opt-in) runs the realm's declared
    extraction producer and keeps the result in the graph. The page is static HTML; there is no crawler,
    queue or extraction service of its own.
