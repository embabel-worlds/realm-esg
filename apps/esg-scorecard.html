ESG scorecard

What an organization's published material actually says — typed, quoted, and rendered in whichever framework you need.

Observations

Every answer carries the sentence it was read from. A figure is a figure; where the material is silent it says so.

Framework codes in this realm are verified: false — provisional, not yet checked against the published standard. Do not quote them onward.

Silence

Read the material and found nothing (not_disclosed) versus never looked (not_assessed). Conflating those is what makes a scraped ESG dataset worthless.

How it works

The data

Everything here is read from this world's graph through the realm-esg views; nothing is fetched from the web by this page. Documents (tagged esg) are put into the corpus by the Populate app, which crawls an organization's site or ingests a report URL. Each EsgObservation is produced by the realm's esgExtraction producer (an extract producer over the document's chunks, one model call per extraction window) and is kept in the graph (cache: { kind: graph }), so a value is as fresh as the last time its document was ingested and read — not as fresh as the company's website today. Datapoint names, answer types and framework requirement codes come from esg-catalogue.json, shipped beside this app, so the page works even where the reference catalogue was never seeded.

The questions

The page calls four named views through POST /api/v1/views/{name}/invoke; it never sends Cypher. On load it reads EsgCoverage to fill the organization list. With observations as captured selected it first runs EsgExtract for the chosen domain — the one call here that can start model work, reading any document not yet read — then renders EsgProfile. With a framework selected it renders EsgProfile projected through the shipped catalogue's requirement list for that framework (in the browser, not by graph traversal; a requirement with no observation shows not assessed). Both modes then render EsgSilence in the second panel.

EsgCoverage — Which organizations have material in the corpus, with document and chunk counts. Fills the Organization list. No parameters.
MATCH (d:Document) WHERE 'esg' IN d.tags
WITH d, [t IN d.tags WHERE t STARTS WITH 'domain:'][0] AS dt
WITH d, coalesce(
       CASE WHEN dt IS NULL THEN null ELSE substring(dt, 7) END,
       replace(split(replace(replace(d.uri, 'https://', ''), 'http://', ''), '/')[0], 'www.', '')
     ) AS domain
OPTIONAL MATCH (c:ContentElement)-[:HAS_PARENT*]->(d:Document)
WITH domain, d, count(DISTINCT c) AS chunkCount
RETURN domain,
       count(DISTINCT d) AS documents,
       sum(chunkCount) AS chunks,
       max(d.ingestionEpochMs) AS lastIngestedEpochMs
ORDER BY domain
EsgExtract — Reads every ingested document for the domain and returns its observations, materializing extraction on first read (ai: {materialize: true}). Run before the observations table. Parameters: domain.
// ANCHOR THE JOIN ON ITS KEY FIELD (`uri`, the producer's anchorKeyProperty): the planner
// materializes a virtual join only when it finds a predicate on that key in the pattern.
// `ai: {materialize: true}` is the EXPLICIT opt-in past the cold-materialization cost gate,
// which refuses a query whose ESTIMATED cold model calls exceed the configured ceiling. Right
// for a passive read; wrong here — this view exists to READ documents and is what the Populate
// button calls, so the cost is the thing the user just asked for.
//
// Without it the failure is silent and LOAD-DEPENDENT: axa.com's two pages (280 + 86 chunks,
// ~7 windows) were refused together while either alone succeeded, and the refusal arrived as
// "the request was too broad" with no warning and no producer log line — one company silently
// skipped while the run reported success.
//
// The other views deliberately do NOT carry this: opening a scorecard must not be able to
// start an unbounded extraction run.
MATCH (d:Document)-[:HAS_OBSERVATIONS {ai: {materialize: true}}]->(o:EsgObservation)
WHERE d.uri CONTAINS $domain
// ONE ANSWER PER DATAPOINT. A long document is extracted in WINDOWS and every window answers
// every datapoint — AXA's 280-chunk page makes five, so it holds 5 x 14 = 70 rows, most of them
// the not_disclosed of a window that simply did not contain the relevant text. Returned raw,
// that makes a well-extracted company look mostly silent and wrecks any rate computed over
// rows. Prefer a window that actually found something, and report how many did.
// Pick by AGREEMENT, not arrival order. A long report has many tables — prior-year columns,
// component sub-totals, restatements — so windows legitimately disagree, and taking the first
// is a coin toss that reads as an answer. Espersen's 384-chunk report produced Scope 1 of both
// 3,332 tCO2e (the total) and 184.2 tCO2e (company cars alone); first-wins reported neither
// reliably. The value the most windows independently found is the total far more often than
// not, and `candidateValues` says how much disagreement is hiding behind the number: anything
// above 1 deserves a human before it is quoted.
WITH o.datapointId AS dpId, collect(o) AS obs
WITH dpId, obs, [x IN obs WHERE x.value <> 'not_disclosed'] AS said
UNWIND (CASE WHEN size(said) > 0 THEN said ELSE obs END) AS cand
WITH dpId, obs, said, cand.value AS v, collect(cand) AS sameValue
WITH dpId, obs, said, v, sameValue, size(sameValue) AS agreeing
ORDER BY agreeing DESC, v
WITH dpId, obs, said, collect({o: sameValue[0], v: v, agreeing: agreeing}) AS ranked
WITH dpId, ranked[0].o AS o,
     size(said) AS windowsDisclosing,
     size(obs) AS windowsRead,
     ranked[0].agreeing AS windowsAgreeing,
     size(ranked) AS candidateValues
RETURN o.docUri AS document, dpId AS datapoint, o.value AS value,
       o.unit AS unit, o.period AS period, o.quote AS quote, o.sourceChunkId AS chunkId,
       windowsDisclosing, windowsRead, windowsAgreeing, candidateValues
ORDER BY datapoint
EsgProfile — One answer per datapoint for the domain, picked by agreement across extraction windows, with the verbatim quote and source URL. Feeds the main table in both modes. Parameters: domain.
// READS PERSISTED OBSERVATIONS. Deliberately NOT through (d:Document)-[:HAS_OBSERVATIONS]->:
// that edge is a virtual join, so touching it puts the query in front of the cold-materialization
// cost gate, which estimates from CHUNK COUNT and cannot tell that everything is already
// extracted. The result was that this view failed with "too broad" for precisely the
// best-documented companies — espersen (182 observations across 629 chunks) and axa (125) both
// refused, while schott with 9 chunks answered fine.
//
// Observations are ordinary persisted nodes since the producer declared cache: { kind: graph },
// so a read can just read them. EsgExtract remains the one view that materializes, which is its
// whole job; every other view is now free and cannot start a model call.
MATCH (o:EsgObservation) WHERE o.docUri CONTAINS $domain
WITH o.datapointId AS dpId, collect(o) AS obs
WITH dpId, obs, [x IN obs WHERE x.value <> 'not_disclosed'] AS said
UNWIND (CASE WHEN size(said) > 0 THEN said ELSE obs END) AS cand
WITH dpId, obs, said, cand.value AS v, collect(cand) AS sameValue
WITH dpId, obs, said, v, sameValue, size(sameValue) AS agreeing
ORDER BY agreeing DESC, v
WITH dpId, obs, said, collect({o: sameValue[0], v: v, agreeing: agreeing}) AS ranked
WITH dpId, ranked[0].o AS o,
     size(said) AS windowsDisclosing,
     size(obs) AS windowsRead,
     ranked[0].agreeing AS windowsAgreeing,
     size(ranked) AS candidateValues
OPTIONAL MATCH (dp:EsgDatapoint {id: dpId})
RETURN coalesce(dp.name, dpId) AS datapoint, dp.answerType AS type, o.value AS value,
       o.unit AS unit, o.period AS period, o.confidence AS confidence, o.quote AS evidence,
       o.docUri AS sourceUrl, o.sourceChunkId AS chunkId,
       windowsDisclosing, windowsRead, windowsAgreeing, candidateValues
ORDER BY datapoint
EsgSilence — Datapoints the material is silent on (not_disclosed) versus never read (not_assessed). Feeds the Silence panel. Parameters: domain.
MATCH (dp:EsgDatapoint)
OPTIONAL MATCH (d:Document)-[:HAS_OBSERVATIONS]->(o:EsgObservation)
  WHERE d.uri CONTAINS $domain AND o.datapointId = dp.id
WITH dp, o
WHERE o IS NULL OR o.value = 'not_disclosed'
RETURN dp.name AS datapoint, dp.answerType AS type,
       CASE WHEN o IS NULL THEN 'not_assessed' ELSE 'not_disclosed' END AS status
ORDER BY status, dp.name

When it looks wrong

  • nothing to show — populate this domain first: the view returned no rows — the organization has no observations yet. Use the Populate app; an absent company has not been assessed, which is not the same as having disclosed nothing.
  • could not load: …: a view failed or reported FAILED; the message is the appliance's own.
  • nothing assessed yet — use Populate / coverage unavailable in the list: EsgCoverage returned no rows, or could not be read.
  • The first observations read of a newly ingested company is slow (EsgExtract makes one model call per extraction window); later reads are instant until the document changes.
  • In a framework rendering, codes are flagged verified: false — provisional, not yet checked against the published standard. A row marked not assessed means no observation exists for that datapoint, not that the company is silent.
  • Units are as published and never converted.

What made this possible

Extraction is a declared producer over a virtual join (HAS_OBSERVATIONS): the first query that traverses it with an explicit materialize opt-in runs the model over the document's chunks and keeps the typed observations in the graph, so every later read is an ordinary graph query. The page is static HTML that asks the world for views by name; there is no backend of its own to deploy.
